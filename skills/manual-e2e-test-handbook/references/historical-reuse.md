# 历史手册存储与复用

本规则用于在 skill 自有目录中积累跨项目测试资产，同时防止项目串档、陈旧结论复用和敏感信息泄露。

## 存储根目录

默认根目录：

```text
%USERPROFILE%\.codex\skills\manual-e2e-test-handbook\workspace
```

运行时结构：

```text
workspace/
|-- 全局索引.md
|-- 跨项目测试经验库.md
`-- projects/
    `-- <project-key>/
        |-- 项目信息.md
        |-- 索引.md
        |-- handbooks/
        |   `-- <功能名>_<版本>_<run-id>_人工测试手册.md
        |-- manifests/
        |   `-- <功能名>_<版本>_<run-id>_改造范围清单.md
        |-- runs/
        |   `-- <run-id>/
        |       |-- run-state.json
        |       |-- event-journal.jsonl
        |       |-- machine-results.md
        |       |-- command-ledger.md
        |       `-- evidence/
        |-- evidence/
        `-- 测试经验.md
```

不要预先创建空目录。测试开始时把本轮需要创建的目录及文件纳入一次性批量确认；确认后可直接创建和更新已列出的目标，不再逐文件申请确认。

## 每轮批量授权

在启动容器、写测试数据或首次写文档之前，固定 `project-key` 和 `run-id`，先按约定生成本轮唯一的最终手册路径：`projects/<project-key>/handbooks/<功能名>_<版本>_<run-id>_人工测试手册.md`，再一次列出本轮预计产生的准确文件：范围清单、这一个最终人工测试手册、运行状态、事件日志、机器结果、命令台账、脱敏证据、项目信息、项目索引、全局索引、项目经验及跨项目经验。无法预先确定单个证据文件名时，只能使用绑定该 run-id 的有界模式，例如 `runs/<run-id>/evidence/*.log`，不能使用无界模式。

用户确认后，该授权覆盖本轮已列文件的创建和更新，包括写入失败后的幂等补齐、最终手册落盘和索引合并。本轮内不再逐文件确认；后续测试通过项目索引和全局索引读取该手册及其关联经验。授权在本轮完成或放弃时终止，也不能转用于另一个项目或 run-id。

出现以下任一情况必须重新确认：新增未列出的文件或目录；写到 skill workspace 之外；扩大容器、服务、接口或数据范围；删除、移动、重命名历史文件；执行未批准的破坏性清理；根据失败诊断修改代码、配置、迁移、测试数据或服务状态。

## 项目标识

项目记录必须隔离。按以下优先级生成稳定 `project-key`：

1. 规范化的 Git remote 主机、组织和仓库名，加短指纹；
2. 没有 remote 时，使用仓库根目录规范化路径的短指纹；
3. 非 Git 项目使用明确项目名和规范化绝对路径的短指纹。

规范化时移除协议、凭据、末尾 `.git` 和多余分隔符，再转为小写；短指纹使用规范化身份文本的 SHA-256 前 10 个十六进制字符。`project-key` 使用 ASCII 小写字母、数字和连字符。`项目信息.md` 保存用于重新识别项目的脱敏证据及历史身份别名。检测到同名但指纹不同的项目时必须创建不同 key，不得自动合并；remote 重命名、迁移或路径变化时，只有在用户确认身份连续性后才登记别名。

每次测试运行生成唯一 `run-id`：`YYYYMMDD-HHMMSS-<测试提交前7位>`；没有提交时使用范围清单修订号。运行手册和范围清单视为不可变记录，不得覆盖同名文件；发生冲突时生成新的 run-id。

## 检索顺序

每次执行按以下顺序读取，避免把整个历史库装入上下文：

1. `全局索引.md`：按项目、模块、API、表、Redis key、消息主题和标签筛选候选记录；
2. 当前项目的 `索引.md`、最新范围清单及相关历史手册；
3. 当前项目的 `测试经验.md`；
4. 仅在存在明确技术匹配时读取 `跨项目测试经验库.md` 中的对应条目。

索引条目至少记录：文档 ID、项目 key、标题、模块/接口/数据标签、基线、测试版本、状态、最后验证时间、文件路径和失效条件。

## 复用门槛

历史资料只能提供候选启动方式、数据构造、Case、排查路径和回归关系。复用前必须：

- 对照当前代码、diff、Compose、接口、schema、缓存和消息定义；
- 检查历史条目的适用版本与失效条件；
- 将 `Valid`、`Stale` 或 `Rejected` 结论写入本次手册；
- 在当前版本重新执行命令和 Case；
- 重新产生当前运行的结果证据。

不得继承旧手册的 `Pass`，不得因历史手册没有某项回归就判断当前无需回归。历史与当前证据冲突时，以当前代码和实测为准，并更新索引中的陈旧状态。

## 经验沉淀与晋升

项目经验包括已验证的启动顺序、稳定数据构造、常见失败、诊断路径、恢复步骤和回归组合。每条经验记录：稳定 ID、适用范围、来源 Case/Failure、最后验证版本和时间、失效条件。

只有满足以下条件才晋升到跨项目经验库：

- 不依赖单一业务语义或内部标识；
- 至少有一次可引用的成功验证证据；
- 明确适用技术、前置条件和失效条件；
- 已移除凭据、Token、个人信息、客户数据、生产数据和敏感日志；
- 不包含只能在某一仓库成立的未验证假设。

跨项目经验在新项目中仍是候选建议，必须重新验证。

## 写入一致性

1. 使用 run-id 先写本次范围清单、命令台账和最终手册到已授权的确定路径，并在 `run-state.json` 中记录 `manifest_path`、`handbook_path`、`command_ledger_path` 和本轮授权摘要；重新读取确认文件完整。
2. 成功后立即重新读取项目索引，按文档 ID 合并并更新，避免覆盖刚出现的新条目。
3. 再重新读取全局索引，按文档 ID 合并并更新。
4. 最后追加或修订经验条目；经验条目也使用稳定 ID 去重。

命令台账和证据在每条命令后写入；事件日志、运行状态、机器结果和手册在每个 Case 后按顺序同步。手册在首个 Case 前创建为 `Draft/Running`，每次同步递增 `handbook_revision` 并更新 `last_synced_case`，全部通过且清理完成后才改为 `Machine-validated/Done`。状态文件记录当前控制点，事件日志记录不可变事实。恢复时先读取状态、最近事件、命令台账和手册最新章节，再核对当前代码、Compose 和容器状态。

任何一步失败都报告已写入和未写入的文件，不伪造索引完成状态。重新执行时复用相同文档 ID并补齐缺失索引，不重复生成已完整的运行文件。修订既有手册时保留历史版本或明确版本号，不静默覆盖不同测试版本的结果。

运行文件是事实来源，索引是可重建视图。读取索引时检查目标路径存在、文档 ID 唯一且项目 key 匹配；发现损坏、遗漏或孤儿条目时先报告差异。若索引重建已列入本轮批量授权，可直接重建；否则重新确认。多个会话可能同时写入时，必须在最终写索引前重新读取并合并；无法证明未覆盖其他会话更新时停止写入并报告冲突。

## 生命周期限制

skill 目录适合本机跨项目复用，但不是天然备份。skill 重装、目录迁移或人工删除可能丢失 `workspace/`。维护或升级本 skill 时不得删除、覆盖或批量重建 `workspace/`；知识积累重要时，提醒用户将该目录备份到其选择的位置。
