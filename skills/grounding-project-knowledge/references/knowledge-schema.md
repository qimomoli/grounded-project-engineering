# Project Knowledge Schema

Read this reference before constructing or changing a project knowledge entry.

## Storage

Each project is stored under `knowledge/projects/<project-key>/`:

```text
project.json
entries/<entry-id>.json
```

`project-key` is derived from a normalized Git origin when available. Otherwise it is derived from a normalized absolute project root. Different worktrees of the same remote share a key; unrelated projects never share facts.

`knowledge/projects/_workspace/` is reserved for machine-local repository
registration and cross-project navigation. It is not a project key and is
validated by [workspace-schema.md](workspace-schema.md).

## Candidate And Stored Fields

An `upsert` candidate omits `entry_id` and `project_key`; the store derives and
injects both. A durable entry must contain every field in the table. Supplying a
different generated value is rejected.

| Field | Type | Contract |
|---|---|---|
| `schema_version` | integer | Must equal `1` |
| `entry_id` | string | Deterministically generated by the store |
| `project_key` | string | Must match the resolved current project |
| `kind` | string | One of `build`, `call-flow`, `configuration`, `data-model`, `dependency`, `error-handling`, `interface`, `module-role`, `security-boundary`, or `state-transition` |
| `title` | string | Short retrieval label |
| `claim` | string | One independently verifiable fact |
| `scope` | string array | Existing project-relative files affected by the fact; every evidence path must appear here |
| `evidence` | object array | One or more current source anchors |
| `verified_at` | string | Valid UTC ISO-8601 timestamp ending in `Z` |
| `status` | string | `current`, `needs-reverification`, or `retired` |

Every evidence object contains:

| Field | Type | Contract |
|---|---|---|
| `kind` | string | `source`, `runtime-config`, `build-definition`, `migration`, or `interface-definition` |
| `path` | string | Project-relative file path without `.` or `..` segments |
| `symbol` | string | Non-empty function, class, key, migration, target, or other precise anchor |
| `line_start` | integer | One-based first evidence line |
| `line_end` | integer | One-based final evidence line, not before `line_start` and not beyond the file |
| `sha256` | string | Lowercase SHA-256 of the complete referenced file |

## Status Transitions

- Create or refresh `current` only after reading current source and matching every evidence hash.
- Change `current` to `needs-reverification` when an evidence file changes or disappears.
- Restore `current` only after re-reading and re-establishing the claim.
- Change to `retired` when current source proves the fact no longer describes the system but historical retention remains useful.
- Never automatically delete durable entries.

## Evidence Boundary

The following may guide a search but cannot appear as the sole evidence for a fact:

- README, Wiki, design documents, tickets, chats, and commit messages.
- Code comments without supporting executable or parsed structure.
- Tests without matching production implementation.
- Knowledge from another project key.
- Model memory or plausible similarity.

Common documentation extensions such as `.md`, `.rst`, and `.txt` are rejected
even if labeled as `source`. Do not store secrets, tokens, credentials, personal
data, or large source excerpts. Secret-pattern checks reduce accidental capture;
they are not a complete secret scanner, so inspect candidate content before upsert.

## Complete Example

```json
{
  "schema_version": 1,
  "entry_id": "7f62b8f9670f061b48f2",
  "project_key": "demo-2d0c0a754f23",
  "kind": "call-flow",
  "title": "API handler dispatches through router",
  "claim": "ApiController.handle delegates request selection to DispatchService.route",
  "scope": [
    "src/api/controller.py",
    "src/service/dispatch.py"
  ],
  "evidence": [
    {
      "kind": "source",
      "path": "src/api/controller.py",
      "symbol": "ApiController.handle",
      "line_start": 24,
      "line_end": 31,
      "sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
    }
  ],
  "verified_at": "2026-10-23T08:00:00Z",
  "status": "current"
}
```

The SHA-256 in this illustrative example must be replaced with the actual current file digest before `upsert`.

## CLI Sequence

Use the available Python 3 runtime. On this machine it is:

```text
python
```

Run `resolve-project`, then `revalidate`, then a filtered `query`. For an explicitly
read-only task, use `revalidate --check-only` and manually compare any reported
entry with current source. For maintenance, start `upsert --project-root <root>
--candidate -` and send exactly one JSON object on stdin. A successful command
prints the durable entry path; validation failure returns exit code `2` without
changing the previous entry.
